## 4. 新增商铺

### POST `/shop`

新增商铺信息。

**状态：🟢 已实现**

**请求头：** `Authorization: <token>`

**请求体（Shop）：**
```json
{
  "name": "新白鹿餐厅(运河上街店)",
  "typeId": 1,
  "images": "img1.jpg,img2.jpg,img3.jpg",
  "area": "运河上街",
  "address": "台州路2号运河上街购物中心F5",
  "x": 120.151954,
  "y": 30.32497,
  "avgPrice": 61,
  "sold": 0,
  "comments": 0,
  "score": 47,
  "openHours": "10:30-21:00"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| name | String | 是 | 商铺名称 |
| typeId | Long | 是 | 类型 ID |
| images | String | 是 | 图片路径，逗号分隔 |
| area | String | 否 | 商圈 |
| address | String | 是 | 详细地址 |
| x | Double | 是 | 经度 |
| y | Double | 是 | 纬度 |
| avgPrice | Long | 否 | 人均价格（元） |
| sold | Integer | 否 | 销量，默认 0 |
| comments | Integer | 否 | 评论数，默认 0 |
| score | Integer | 否 | 评分 ×10（如 37=3.7分） |
| openHours | String | 否 | 营业时间 |

**成功响应：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": 15,
  "total": null
}
```

> **说明**：`data` 返回新商铺的 ID（Long 类型）。

## 5. 更新商铺信息

### PUT `/shop`

更新商铺信息。

**状态：🟢 已实现**

**请求头：** `Authorization: <token>`

**请求体（Shop）：** 同新增，但必须包含 `id` 字段。

```json
{
  "id": 1,
  "name": "103茶餐厅(旗舰店)",
  "avgPrice": 88
}
```

> 只传需要更新的字段即可，MyBatis-Plus 的 `updateById` 会忽略 null 字段。

**成功响应：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": null,
  "total": null
}
```

**实现优化建议：**
更新商铺后应主动删除或更新 Redis 缓存：
```java
// 更新 DB 后
stringRedisTemplate.delete(RedisConstants.CACHE_SHOP_KEY + shop.getId());
```

## 8. 附近商铺查询（GEO）

### GET `/shop/nearby`

根据用户位置查询附近商铺，按距离排序。

**状态：🔴 待实现**

**请求参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| typeId | Integer | 否 | — | 商铺类型 ID（不传查全部类型） |
| x | Double | 是 | — | 用户当前经度 |
| y | Double | 是 | — | 用户当前纬度 |
| radius | Integer | 否 | 5000 | 搜索半径（米），默认 5km |
| current | Integer | 否 | 1 | 当前页码 |

**业务规则：**
1. 使用 Redis GEO 数据结构存储商铺坐标
2. 第一次查询时，若 Redis 无数据，从 MySQL 加载并批量 `GEOADD` 到 Redis
3. 使用 `GEOSEARCH` 命令按半径搜索（Redis 6.2+）或 `GEORADIUS`（旧版）

**Redis 存储设计：**
```
GEOADD shop:geo:{typeId} {经度} {纬度} {商铺ID}
GEORADIUS shop:geo:{typeId} {经度} {纬度} {半径}m WITHDIST ASC
```

**实现伪代码：**
```java
// 1. 构建 key
String key = typeId != null
    ? RedisConstants.SHOP_GEO_KEY + typeId
    : RedisConstants.SHOP_GEO_KEY + "all";

// 2. 执行 GEO 搜索
List<GeoResult<RedisGeoCommands.GeoLocation<String>>> results =
    stringRedisTemplate.opsForGeo().radius(
        key,
        new Circle(new Point(x, y), new Distance(radius, Metrics.METERS)),
        RedisGeoCommands.GeoRadiusCommandArgs.newGeoRadiusArgs()
            .includeDistance().sortAscending()
            .limit((current - 1) * pageSize, pageSize)
    );

// 3. 提取 shopId 列表，批量查询 MySQL 填充详情
// 4. 计算距离并注入 distance 字段
```

**成功响应：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": [
    {
      "id": 1,
      "name": "103茶餐厅",
      "typeId": 1,
      "images": "...",
      "area": "大关",
      "address": "金华路锦昌文华苑29号",
      "avgPrice": 80,
      "score": 37,
      "distance": 1.2
    },
    {
      "id": 3,
      "name": "新白鹿餐厅(运河上街店)",
      "typeId": 1,
      "images": "...",
      "area": "运河上街",
      "avgPrice": 61,
      "score": 47,
      "distance": 2.8
    }
  ],
  "total": null
}
```

> `distance` 单位为**公里（km）**。

## 9. 数据字典

### 商铺类型表 (tb_shop_type)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键，自增 |
| name | varchar(32) | 类型名称 |
| icon | varchar(255) | 图标路径 |
| sort | int | 排序权重 |

### 商铺表 (tb_shop)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键，自增 |
| name | varchar(128) | 商铺名称 |
| type_id | bigint | 类型 ID，关联 tb_shop_type.id |
| images | varchar(1024) | 图片列表，逗号分隔 |
| area | varchar(128) | 商圈 |
| address | varchar(255) | 详细地址 |
| x | double | 经度 |
| y | double | 纬度 |
| avg_price | bigint | 人均价格（元，整数） |
| sold | int | 累计销量 |
| comments | int | 评论数量 |
| score | int | 评分 ×10（例：37 = 3.7） |
| open_hours | varchar(32) | 营业时间 |
| create_time | timestamp | 创建时间 |
| update_time | timestamp | 更新时间 |

### Redis Key 设计

| Key | 类型 | 说明 |
|-----|------|------|
| `cache:shop:{id}` | String(JSON) | 商铺详情缓存，逻辑过期 |
| `lock:shop:{id}` | String | 缓存重建互斥锁 |
| `shop:geo:{typeId}` | GEO | 按类型的商铺坐标 |
