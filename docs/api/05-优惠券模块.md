## 2. 新增普通优惠券

### POST `/voucher`

新增一张普通代金券。

**状态：🟢 已实现**

**请求头：** `Authorization: <token>`

**请求体（Voucher）：**
```json
{
  "shopId": 1,
  "title": "50元代金券",
  "subTitle": "满100元可用",
  "rules": "1. 仅限堂食\n2. 不可与其他优惠叠加\n3. 每桌限用一张",
  "payValue": 5000,
  "actualValue": 5000,
  "type": 0,
  "status": 1
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| shopId | Long | 是 | 所属商铺 ID |
| title | String | 是 | 代金券标题 |
| subTitle | String | 是 | 副标题/使用条件 |
| rules | String | 否 | 使用规则（文本） |
| payValue | Long | 是 | 支付金额（分）例：5000 = ¥50.00 |
| actualValue | Long | 是 | 抵扣金额（分）例：5000 = ¥50.00 |
| type | Integer | 是 | 券类型：0=普通券，1=秒杀券 |
| status | Integer | 是 | 状态：0=下架，1=上架 |

> **金额约定**：`payValue` 和 `actualValue` 以「分」为单位。当二者相等时即为免费领取；当 `payValue < actualValue` 时为折扣购买。

**成功响应：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": 1,
  "total": null
}
```

> `data` 为新券的 ID。

## 3. 新增秒杀优惠券

### POST `/voucher/seckill`

新增一张秒杀优惠券（含秒杀时间和库存信息）。

**状态：🟢 已实现**（`VoucherServiceImpl.addSeckillVoucher` 使用 `@Transactional` 保证原子性）

**请求头：** `Authorization: <token>`

**请求体（Voucher + 秒杀字段）：**
```json
{
  "shopId": 1,
  "title": "100元秒杀券",
  "subTitle": "限量100张，手慢无",
  "rules": "1. 每人限购1张\n2. 有效期30天",
  "payValue": 1000,
  "actualValue": 10000,
  "type": 1,
  "status": 1,
  "stock": 100,
  "beginTime": "2022-01-20T10:00:00",
  "endTime": "2022-02-20T23:59:59"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| shopId | Long | 是 | 所属商铺 ID |
| title | String | 是 | 券标题 |
| subTitle | String | 是 | 副标题 |
| rules | String | 否 | 使用规则 |
| payValue | Long | 是 | 支付金额（分） |
| actualValue | Long | 是 | 抵扣金额（分） |
| type | Integer | 是 | 必须为 1（秒杀券） |
| status | Integer | 是 | 状态：0=下架，1=上架 |
| **stock** | **Integer** | **是** | **库存数量**（存在 `tb_seckill_voucher`） |
| **beginTime** | **String** | **是** | **秒杀开始时间** |
| **endTime** | **String** | **是** | **秒杀结束时间** |

> `stock`、`beginTime`、`endTime` 是 Voucher 实体的 `@TableField(exist=false)` 瞬态字段，通过 `addSeckillVoucher` 方法分别写入 `tb_voucher` 和 `tb_seckill_voucher` 两张表。

**业务规则：**
1. `@Transactional` 保证两张表同步写入
2. 先保存 `tb_voucher`（主表），获取自增 ID
3. 将 ID 作为 `voucher_id` 写入 `tb_seckill_voucher`

**成功响应：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": 2,
  "total": null
}
```

### GET `/voucher/list/{shopId}`

查询某店铺的所有在售优惠券（含秒杀券信息）。

**状态：🟢 已实现**

**路径参数：**

| 参数 | 类型 | 说明 |
|------|------|------|
| shopId | Long | 商铺 ID |

**业务规则：**
- 通过 `VoucherMapper.queryVoucherOfShop` 执行 **LEFT JOIN** 关联 `tb_seckill_voucher`
- 返回普通券 + 秒杀券的合并列表

```sql

       sv.stock, sv.begin_time, sv.end_time
FROM tb_voucher v
LEFT JOIN tb_seckill_voucher sv ON v.id = sv.voucher_id
WHERE v.shop_id = #{shopId}
  AND v.status = 1
```

## 5. 秒杀下单

### POST `/voucher-order/seckill/{id}`

抢购一张秒杀优惠券。这是整个项目中**并发压力最大**的接口。

**状态：🔴 待实现（当前返回"功能未完成"）**

**路径参数：**

| 参数 | 类型 | 说明 |
|------|------|------|
| id | Long | 秒杀券的 voucher_id |

**请求头：** `Authorization: <token>`

**业务规则（高并发方案）：**

```
┌─────────────────────────────────────────────────────────┐
│ 1. 校验秒杀时间 (begin_time ≤ now ≤ end_time)            │
│ 2. 校验一人一单 (Redis Set 判重)                         │
│ 3. Redis 预减库存 (DECR seckill:stock:{voucherId})       │
│    └─ 库存不足 → 直接返回"已抢光"                         │
│ 4. 发送消息队列 (RocketMQ / Redis Stream)                 │
│ 5. 异步消费 → 创建订单 (MySQL)                            │
│    └─ 失败 → 回滚 Redis 库存 (INCR)                       │
└─────────────────────────────────────────────────────────┘
```

**请求示例：**
```
POST /api/voucher-order/seckill/2
```

**成功响应：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": 20220120100001,
  "total": null
}
```

> `data` 为生成的订单 ID（Long，使用雪花算法或时间戳生成）。

**失败响应（按优先级）：**

| 场景 | HTTP | errorMsg |
|------|------|----------|
| 秒杀未开始 | 200 | `"秒杀尚未开始"` |
| 秒杀已结束 | 200 | `"秒杀已结束"` |
| 已抢过该券 | 200 | `"每人限购一张"` |
| 库存已抢光 | 200 | `"优惠券已抢光"` |
| 未登录 | 401 | — |
| 服务器异常 | 500 | `"服务器异常"` |

**完整实现代码参考：**

```java
@PostMapping("seckill/{id}")
public Result seckillVoucher(@PathVariable("id") Long voucherId) {
    // 1. 获取当前用户
    UserDTO user = UserHolder.getUser();

    // 2. 校验秒杀时间
    SeckillVoucher seckillVoucher = seckillVoucherService.getById(voucherId);
    LocalDateTime now = LocalDateTime.now();
    if (now.isBefore(seckillVoucher.getBeginTime())) {
        return Result.fail("秒杀尚未开始");
    }
    if (now.isAfter(seckillVoucher.getEndTime())) {
        return Result.fail("秒杀已结束");
    }

    // 3. 一人一单校验 (Redis Set)
    String orderKey = "seckill:order:" + voucherId;
    Boolean isOrdered = stringRedisTemplate.opsForSet()
        .isMember(orderKey, user.getId().toString());
    if (Boolean.TRUE.equals(isOrdered)) {
        return Result.fail("每人限购一张");
    }

    // 4. Redis 预减库存
    String stockKey = RedisConstants.SECKILL_STOCK_KEY + voucherId;
    Long stock = stringRedisTemplate.opsForValue().decrement(stockKey);
    if (stock == null || stock < 0) {
        // 库存不足，恢复
        stringRedisTemplate.opsForValue().increment(stockKey);
        return Result.fail("优惠券已抢光");
    }

    // 5. 标记已下单（防止重复）
    stringRedisTemplate.opsForSet().add(orderKey, user.getId().toString());

    // 6. 发送消息队列 → 异步创建订单
    VoucherOrder order = new VoucherOrder();
    order.setId(nextOrderId());  // 全局唯一 ID 生成
    order.setUserId(user.getId());
    order.setVoucherId(voucherId);
    order.setStatus(1);  // 未支付
    // ... 发送到 RocketMQ / Redis Stream

    return Result.ok(order.getId());
}
```

## 7. 秒杀方案设计

### 7.1 架构选型

| 方案 | 优点 | 缺点 | 推荐场景 |
|------|------|------|----------|
| **纯 MySQL 悲观锁** | 简单 | 性能低，DB 压力大 | 极低并发 |
| **Redis 预减 + MQ 异步** | 高性能，削峰 | 依赖 Redis + MQ | **推荐** |
| **Redis + Lua 原子操作** | 单次原子 | 无法削峰 | 中并发 |

本项目推荐方案：**Redis 预减库存 + 阻塞队列/Stream 异步下单**。

### 7.2 Redis 初始化

秒杀券创建时，将库存同步到 Redis：
```java
// 在 addSeckillVoucher 方法中增加
stringRedisTemplate.opsForValue()
    .set(RedisConstants.SECKILL_STOCK_KEY + voucher.getId(),
         voucher.getStock().toString());
```

### 7.3 Lua 脚本（可选优化）

将校验 + 预减合并为原子操作：
```lua
-- seckill.lua
local voucherId = KEYS[1]
local userId = ARGV[1]
local stockKey = "seckill:stock:" .. voucherId
local orderKey = "seckill:order:" .. voucherId

-- 判断是否已下单
local isOrdered = redis.call('sismember', orderKey, userId)
if isOrdered == 1 then
    return 1  -- 已下单
end

-- 判断库存
local stock = tonumber(redis.call('get', stockKey))
if stock == nil or stock <= 0 then
    return 2  -- 库存不足
end

-- 预减库存 + 标记已下单
redis.call('decr', stockKey)
redis.call('sadd', orderKey, userId)
return 0  -- 成功
```

### 7.4 异步下单流程

```
用户请求 → Controller (同步校验)
              ↓
         Redis 预减库存
              ↓
         发送消息到 Stream
              ↓
         立即返回订单 ID
         
--- 异步 ---

消息消费者:
  ↓ 从 Stream 读取
  ↓ 校验（兜底）
  ↓ MySQL 创建订单
  ↓ Redis 标记已完成
```

### 7.5 库存回滚

以下场景需要回滚 Redis 库存（`INCR seckill:stock:{voucherId}`）：
- 异步创建订单失败
- 用户取消订单
- 订单超时未支付（15 分钟）

### 订单状态流转

```
  下单
   ↓
 未支付 (1) ──取消──→ 已取消 (4)
   ↓ 支付
 已支付 (2) ──核销──→ 已核销 (3)
   ↓ 退款申请
 退款中 (5) ──完成──→ 已退款 (6)
```

### Redis Key 设计

| Key | 类型 | 说明 |
|-----|------|------|
| `seckill:stock:{voucherId}` | String(Number) | 秒杀库存（预减后值） |
| `seckill:order:{voucherId}` | Set | 已下单用户集合（一人一单校验） |
| `stream:order` | Stream | 订单消息队列（Redis 5.0+） |

### 全局订单 ID 生成建议

```java
// 雪花算法（Snowflake）或简化版时间戳方案：
// 格式：年月日时分秒(14位) + 序号(4位) + 用户ID后4位
// 示例：20220120100005 0001 0001
private long nextOrderId() {
    // 使用 Redis INCR 生成自增序列号
    Long increment = stringRedisTemplate.opsForValue()
        .increment("icr:order:" + LocalDate.now());
    // 组合：日期 + 序列号
    String date = LocalDateTime.now().format(
        DateTimeFormatter.ofPattern("yyyyMMddHHmmss"));
    return Long.parseLong(date + String.format("%06d", increment % 1000000));
}
```
