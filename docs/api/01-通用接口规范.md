## 1. 基础信息

### 1.1 服务地址

| 环境 | 地址 | 说明 |
|------|------|------|
| 开发环境 | `http://localhost:8080` | Nginx 端口 |
| API 代理 | `http://localhost:8080/api` | 转发至 Spring Boot :8081 |

### 1.2 架构说明

```
浏览器 → Nginx(:8080) → /api/* 代理 → Spring Boot(:8081)
                       → 其他 → 静态资源 html/hmdp/
```

Nginx 转发 `/api` 请求时自动去除 `/api` 前缀。例如：
- 请求 `http://localhost:8080/api/user/login`
- 实际到达后端：`http://127.0.0.1:8081/user/login`

### 1.3 数据格式

- 请求 `Content-Type`: `application/json`（文件上传除外）
- 响应 `Content-Type`: `application/json`
- 字符编码: **UTF-8**

### 1.4 日期时间格式

- 响应中日期时间统一使用 **ISO 8601** 格式：`yyyy-MM-dd'T'HH:mm:ss`
- 请求中接收时兼容多种格式（由 Jackson 自动解析）
- 纯日期格式：`yyyy-MM-dd`

## 2. 统一响应格式

所有接口返回统一的 JSON 结构，由 `Result` 类封装：

### 2.1 Result 结构

```json
{
  "success": true,           // Boolean — 请求是否成功
  "errorMsg": null,          // String  — 错误信息（成功时为 null）
  "data": {},                // Object  — 业务数据（无数据时为 null）
  "total": null              // Long    — 分页总条数（非分页时为 null）
}
```

### 2.2 响应场景

#### 成功 — 无返回数据
```json
{
  "success": true,
  "errorMsg": null,
  "data": null,
  "total": null
}
```

#### 成功 — 返回单个对象
```json
{
  "success": true,
  "errorMsg": null,
  "data": { "id": 1, "name": "103茶餐厅" },
  "total": null
}
```

#### 成功 — 返回列表（分页）
```json
{
  "success": true,
  "errorMsg": null,
  "data": [ { "id": 1 }, { "id": 2 } ],
  "total": 14
}
```

#### 成功 — 返回列表（不分页）
```json
{
  "success": true,
  "errorMsg": null,
  "data": [ { "id": 1, "name": "美食" }, { "id": 2, "name": "KTV" } ],
  "total": null
}
```

#### 失败
```json
{
  "success": false,
  "errorMsg": "手机号格式错误",
  "data": null,
  "total": null
}
```

### 2.3 前端接收说明

前端 Axios 响应拦截器（`common.js`）会自动解包：
- `response.data` → 即上述 Result JSON
- 若 `success === false` → 进入 `.catch()` 分支，`err` 为 `errorMsg` 字符串
- 若 HTTP 401 → 自动跳转登录页

## 3. 错误码体系

### 3.1 HTTP 状态码

| 状态码 | 含义 | 触发场景 |
|--------|------|----------|
| 200 | OK | 正常请求（含业务失败） |
| 400 | Bad Request | 参数校验失败 |
| 401 | Unauthorized | 未登录/token 过期 |
| 403 | Forbidden | 无权限 |
| 404 | Not Found | 资源不存在 |
| 500 | Internal Server Error | 服务器内部异常 |

### 3.2 全局异常处理

后端 `WebExceptionAdvice` 捕获所有未处理的 `RuntimeException`，统一返回：

```json
{
  "success": false,
  "errorMsg": "服务器异常",
  "data": null,
  "total": null
}
```

> **开发建议**: 后续应细化异常体系，增加业务异常类 `BusinessException`，携带具体错误码和用户友好的错误信息。

## 4. 认证与鉴权

### 4.1 认证流程

```
1. 用户输入手机号 → POST /user/code 获取短信验证码
2. 用户输入验证码 → POST /user/login 换取 token
3. 后续请求 → 请求头携带 Authorization: <token>
```

### 4.2 Token 机制

| 项目 | 说明 |
|------|------|
| 存储位置 | Redis，key: `login:token:<token>` |
| Token 载体 | 随机 UUID |
| 过期时间 | 36000 秒（10 小时） |
| 传递方式 | HTTP Header: `Authorization: <token>` |
| 前端存储 | `sessionStorage.token` |

### 4.3 登录校验

后端通过 **拦截器**（LoginInterceptor）校验：
1. 从请求头获取 `Authorization` 值
2. 从 Redis 查找对应 token 的用户信息
3. 将用户信息存入 `UserHolder`（ThreadLocal）
4. Token 不存在/过期 → 返回 **HTTP 401**

### 4.4 获取当前用户

在 Controller 层通过以下方式获取当前登录用户：

```java
UserDTO user = UserHolder.getUser();
// user.getId(), user.getNickName(), user.getIcon()
```

## 5. 分页规范

### 5.1 传统分页（Page）

适用于列表查询，使用 MyBatis-Plus 的 `Page` 对象。

**请求参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| current | Integer | 否 | 1 | 当前页码（从 1 开始） |

**响应说明：**
- `data` 包含当前页记录列表
- 分页大小由后端 `SystemConstants` 控制：
  - `DEFAULT_PAGE_SIZE = 5`（商铺按类型查询）
  - `MAX_PAGE_SIZE = 10`（商铺按名称查询、博客列表等）

### 5.2 滚动分页（Scroll Result）

适用于 Feed 流等按时间线滚动的场景，使用 Redis ZSet 实现。

**响应数据 `ScrollResult`：**

```json
{
  "success": true,
  "data": {
    "list": [ ... ],         // 本次返回的记录列表
    "minTime": 1640000000000, // 本次返回的最小时间戳（作为下次请求的 offset）
    "offset": 5              // 偏移量（本次取到的与最小时间戳相同值的个数）
  },
  "total": null
}
```

**请求时透传上一次的 `minTime` 和 `offset` 作为下次查询的游标。**

## 6. 请求规范

### 6.1 请求头

| Header | 值 | 必填 | 说明 |
|--------|------|------|------|
| Content-Type | application/json | 是 | 文件上传除外 |
| Authorization | `<token>` | 条件 | 需要登录的接口必传 |

### 6.2 命名规范

- RESTful 风格
- URL 全部小写，单词间用 `-` 分隔
- 资源名使用名词复数（或不可数单数）
- 路径参数使用驼峰命名

```
正确: GET  /shop-type/list
正确: GET  /voucher-order/seckill/{voucherId}
正确: GET  /blog/of/type?typeId=1&current=1
```

### 6.3 HTTP 方法语义

| 方法 | 语义 | 幂等 |
|------|------|------|
| GET | 查询资源 | 是 |
| POST | 新增资源 | 否 |
| PUT | 全量更新 / 特殊动作 | 是 |
| DELETE | 删除资源 | 是 |

## 7. 缓存策略

### 7.1 Redis Key 设计

| Key Pattern | TTL | 说明 |
|-------------|-----|------|
| `login:code:{phone}` | 2 min | 短信验证码 |
| `login:token:{token}` | 10 h | 登录用户信息 |
| `cache:shop:{id}` | 30 min | 商铺缓存（逻辑过期） |
| `lock:shop:{id}` | 10 s | 商铺缓存重建锁 |
| `seckill:stock:{voucherId}` | — | 秒杀库存预减 |
| `blog:liked:{blogId}` | — | 笔记点赞用户集合 |
| `feed:{userId}` | — | 关注用户 Feed 收件箱 |
| `shop:geo:{typeId}` | — | 商铺 GEO 位置 |
| `sign:{userId}:{year}:{month}` | — | 用户签到位图 |

### 7.2 缓存更新策略

| 场景 | 策略 | 说明 |
|------|------|------|
| 商铺详情 | 逻辑过期 + 互斥锁重建 | 避免缓存雪崩 |
| 空值缓存 | 短期 TTL (2 min) | 防止缓存穿透 |
| 秒杀库存 | Redis 预减 + 异步下单 | 保证高并发下的库存一致性 |

## 8. 通用约定

### 8.1 金额单位

所有金额字段以 **分（cent）** 为单位存储和传输，前端通过 `util.formatPrice()` 方法转为元显示。

```java
// 后端实体
private Long payValue;    // 支付金额，单位：分
private Long actualValue; // 抵扣金额，单位：分
private Long avgPrice;    // 人均价格，单位：元（整数）
```

### 8.2 评分

评分 `score` 为实际分数 ×10 的整数值。例如评分 3.7 → 存储值 37。前端展示时需除以 10。

### 8.3 图片路径

- 数据库存储的是相对路径，如 `/imgs/blogs/7/14/xxx.jpg`
- 前端拼接完整 URL 访问：`/imgs/` + 相对路径
- 上传目录（`SystemConstants.IMAGE_UPLOAD_DIR`）：`D:\lesson\nginx-1.18.0\html\hmdp\imgs\`

### 8.4 手机号

- 格式：11 位数字，正则 `^1[3-9]\d{9}$`
- `tb_user.phone` 有唯一索引

### 8.5 密码

- 加密方式：**Salt + MD5**（`PasswordEncoder`）
- 密码传输时不需要前端二次加密（与验证码登录互斥）

### 8.6 JSON 序列化

- `spring.jackson.default-property-inclusion: non_null`
- 值为 `null` 的字段不会被序列化到响应中
