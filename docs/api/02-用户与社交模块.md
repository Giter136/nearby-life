## 2. 短信验证码

### POST `/user/code`

发送短信验证码到指定手机号。

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| phone | String | 是 | 11位手机号，Query 参数 |

**业务规则：**
1. 校验手机号格式（正则 `^1[3-9]\d{9}$`）
2. 生成 6 位随机数字验证码
3. 存入 Redis：`login:code:{phone}`，TTL = 2 分钟
4. 调用短信服务发送（开发阶段可打印到日志）

**请求示例：**
```
POST /api/user/code?phone=13686869696
```

**成功响应：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": null,
  "total": null
}
```

**失败响应：**
```json
{
  "success": false,
  "errorMsg": "手机号格式错误",
  "data": null,
  "total": null
}
```

**实现要点：**
- 60 秒内不允许对同一手机号重复发送
- 每日同一手机号最多发送 5 次
- 验证码存入 Redis 而非 Session（为分布式做准备）

## 3. 用户登录

### POST `/user/login`

支持两种登录方式：
- **验证码登录**：传入 `phone` + `code`
- **密码登录**：传入 `phone` + `password`

**请求体 (LoginFormDTO)：**

```json
{
  "phone": "13686869696",
  "code": "123456",
  "password": null
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| phone | String | 是 | 11 位手机号 |
| code | String | 条件 | 验证码（验证码登录时必填） |
| password | String | 条件 | 密码（密码登录时必填） |

> **注意**：`code` 和 `password` 互斥，优先判断 `code` 是否为空来决定登录方式。

**业务规则：**

**验证码登录流程：**
1. 从 Redis 查询 `login:code:{phone}` 校验验证码
2. 校验通过后删除 Redis 中的验证码
3. 根据手机号查询 `tb_user`，若不存在则自动注册新用户
4. 生成随机 token（UUID）
5. 将 `UserDTO { id, nickName, icon }` 存入 Redis：`login:token:{token}`，TTL = 10 小时
6. 返回 token

**密码登录流程：**
1. 根据手机号查询 `tb_user`
2. 使用 `PasswordEncoder.verify()` 校验密码
3. 若用户不存在或密码错误 → 返回失败
4. 生成 token 并存入 Redis（同上述步骤 4-6）

**新用户自动注册逻辑：**
```java
User user = new User();
user.setPhone(phone);
user.setNickName(SystemConstants.USER_NICK_NAME_PREFIX + RandomUtil.randomString(10));
user.setIcon("");  // 默认空头像
userService.save(user);
```

**成功响应：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "total": null
}
```

> **说明**：`data` 直接返回 token 字符串（非 JSON 对象），前端存入 `sessionStorage.token`。

**失败响应：**

| 场景 | errorMsg |
|------|----------|
| 验证码错误 | `"验证码错误"` |
| 验证码过期 | `"验证码已过期"` |
| 密码错误 | `"密码错误"` |
| 用户不存在（密码登录） | `"用户不存在"` |
| 手机号格式错误 | `"手机号格式错误"` |

## 6. 用户详情

**路径参数：**

| 参数 | 类型 | 说明 |
|------|------|------|
| id | Long | 用户 ID |

**状态：🟢 已实现**

**业务规则：**
1. 查询 `tb_user_info` 表
2. 若不存在详情 → 返回空 data（`Result.ok()`）
3. 响应中移除 `createTime` 和 `updateTime`

**成功响应（有详情）：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": {

    "city": "杭州",

  "total": null

```

**成功响应（无详情，首次查看）：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": null,
  "total": null
}
```

**data 字段说明（UserInfo）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| userId | Long | 用户 ID |

## 8. 关注与取关

### PUT `/follow/{followUserId}/{isFollow}`

关注或取消关注一个用户。

**路径参数：**

| 参数 | 类型 | 说明 |
|------|------|------|
| followUserId | Long | 目标用户 ID |
| isFollow | Boolean | true=关注，false=取消关注 |

**请求头：** `Authorization: <token>`

**业务规则：**

**关注时：**
1. 校验不能关注自己
2. 校验是否已关注（防重复）
3. 写入 `tb_follow`：`user_id` = 当前用户，`follow_user_id` = 目标用户
4. 更新目标用户的粉丝数 `tb_user_info.fans + 1`
5. 更新当前用户的关注数 `tb_user_info.followee + 1`

**取消关注时：**
1. 删除 `tb_follow` 记录
2. 更新目标用户的粉丝数 `tb_user_info.fans - 1`
3. 更新当前用户的关注数 `tb_user_info.followee - 1`

**成功响应：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": null,
  "total": null
}
```

**失败响应：**
```json
{
  "success": false,
  "errorMsg": "不能关注自己",
  "data": null,
  "total": null
}
```

## 10. 共同关注

### GET `/follow/common/{userId}`

查询当前用户与目标用户的共同关注列表。

**路径参数：**

| 参数 | 类型 | 说明 |
|------|------|------|
| userId | Long | 目标用户 ID |

**请求头：** `Authorization: <token>`

**业务规则：**
1. 分别查询当前用户和目标用户的关注列表
2. 取交集（使用 Redis Set 求交集 或 MySQL 子查询）
3. 返回共同关注的用户基本信息

**成功响应：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": [
    {
      "id": 5,
      "nickName": "可爱多",
      "icon": "/imgs/icons/user5-icon.png"
    },
    {
      "id": 8,
      "nickName": "杭州美食家",
      "icon": "/imgs/icons/default-icon.png"
    }
  ],
  "total": null
}
```

**实现建议：**
```java
// 使用 Redis Set 交集
String key1 = "follows:" + currentUserId;
String key2 = "follows:" + targetUserId;
Set<String> common = redisTemplate.opsForSet().intersect(key1, key2);
```
> 关注时同步维护 Redis Set：`SADD follows:{userId} {followUserId}`
> 取消关注时：`SREM follows:{userId} {followUserId}`

## 11. 用户签到

### POST `/user/sign`

当前用户每日签到。

**请求头：** `Authorization: <token>`

**业务规则：**
1. 校验当天是否已签到（位图判断）
2. 写入 `tb_sign` 表
3. 使用 Redis BitMap 记录签到：`SETBIT sign:{userId}:{year}:{month} {dayOfMonth-1} 1`
4. 签到成功增加积分（如 +5 credits）

**成功响应：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": null,
  "total": null
}
```

**失败响应：**
```json
{
  "success": false,
  "errorMsg": "今日已签到",
  "data": null,
  "total": null
}
```

### GET `/user/sign/count`

查询当前用户本月连续签到天数。

**请求头：** `Authorization: <token>`

**业务规则：**
- 使用 Redis BitMap 的 `BITFIELD` 命令统计连续 1 的位数

**成功响应：**
```json
{
  "success": true,
  "errorMsg": null,
  "data": 7,
  "total": null
}
```

> **说明**：`data` 为 Integer，连续签到天数。

## 12. 数据字典

### 用户表 (tb_user)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键，自增 |
| phone | varchar(11) | 手机号，唯一索引 |
| password | varchar(128) | 密码，Salt + MD5 加密 |
| nick_name | varchar(32) | 昵称，默认 `user_` + 随机字符串 |
| icon | varchar(255) | 头像图片路径 |
| create_time | timestamp | 创建时间 |
| update_time | timestamp | 更新时间 |

### 用户详情表 (tb_user_info)

| 字段 | 类型 | 说明 |
|------|------|------|
| user_id | bigint | 主键，关联 tb_user.id |
| city | varchar(64) | 所在城市 |
| introduce | varchar(256) | 个人介绍 |
| fans | int | 粉丝数 |
| followee | int | 关注数 |
| gender | tinyint | 0=男，1=女 |
| birthday | date | 生日 |
| credits | int | 积分 |
| level | tinyint | 会员等级 0-9 |

### 关注表 (tb_follow)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键，自增 |
| user_id | bigint | 当前用户 ID |
| follow_user_id | bigint | 目标用户 ID |
| create_time | timestamp | 关注时间 |

### 签到表 (tb_sign)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键，自增 |
| user_id | bigint | 用户 ID |
| year | year | 签到年 |
| month | tinyint | 签到月 |
| date | date | 签到日期 |
| is_backup | tinyint | 是否补签：0=正常，1=补签 |

### Redis Key 设计

| Key | 类型 | 说明 |
|-----|------|------|
| `login:code:{phone}` | String | 短信验证码 |
| `login:token:{token}` | Hash | 用户登录态 |
| `follows:{userId}` | Set | 用户关注列表 |
| `sign:{userId}:{year}:{month}` | BitMap | 签到记录 |
